修復驗證通過之後，就進入自動部署。版本號自動遞增：index.json 裡的 version 從 1 變成 2，並且新增了 last_updated 這個欄位，標注為 2026 年 8 月 17 日。接著 Git 自動提交，提交訊息寫得很清楚：「Auto-fix: Self-healing bug fixes 2026-08-17 14:32」。推送到 GitHub 之後，Actions 觸發構建，大約兩分鐘，GitHub Pages 就重建完成。現在線上的版本，就是修復之後的版本。玩家刷新頁面，Service Worker 會自動更新快取，新版本無縫載入，他完全無感。他們永遠看不到壞掉的那一版，也永遠不知道，自己手上這個看起來乾淨俐落的遊戲，背後經歷過三個 Bug、兩次 NIM API 呼叫、和四分鐘的自動修復。這就是自動化管線真正的價值：它把工程的風險，壓縮在一個「開發者看得見、但玩家永遠看不見」的區間裡。你交付給用戶的，永遠是那個「看似從沒出過錯」的成品。
